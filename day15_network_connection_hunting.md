# Day 15 — KQL Network Connection Hunting

## 🎯 Objective

Learn how to investigate **endpoint network connections** and correlate them with processes, users, destinations, and suspicious command-line activity.

Today I practiced:

* `DeviceNetworkEvents`
* Process → Network relationships
* PowerShell network activity
* Download-related PowerShell hunting
* RDP and SMB ports
* Network destination frequency

## 1. What is Network Connection Hunting?

When a process communicates with another system, endpoint telemetry can provide useful information about:

```text
Source Device
Source Process
Destination IP
Destination Port
Protocol
Connection Time
```

In Microsoft Defender XDR, a useful table is:

```kql
DeviceNetworkEvents
```

Important fields include:

```text
Timestamp
DeviceName
InitiatingProcessAccountName
InitiatingProcessFileName
InitiatingProcessCommandLine
RemoteIP
RemotePort
RemoteUrl
Protocol
ActionType
```

The important hunting relationship is:

```text
Account
   ↓
Process
   ↓
Network Connection
   ↓
Destination
   ↓
Investigation
```

---

# 2. Basic Network Hunting

### Mission 1

```kql
DeviceNetworkEvents
| where Timestamp > ago(24h)
| project Timestamp,
          DeviceName,
          InitiatingProcessAccountName,
          InitiatingProcessFileName,
          RemoteIP,
          RemotePort,
          RemoteUrl
```

This provides a basic view of network connections generated by endpoints during the last 24 hours.

---

# 3. PowerShell Network Activity

PowerShell network connections can be legitimate, but suspicious command-line behavior combined with network activity deserves additional investigation.

### Mission 2

```kql
DeviceNetworkEvents
| where Timestamp > ago(24h)
| where InitiatingProcessFileName =~ "powershell.exe"
| project Timestamp,
          DeviceName,
          InitiatingProcessAccountName,
          InitiatingProcessFileName,
          InitiatingProcessCommandLine,
          RemoteIP,
          RemotePort,
          RemoteUrl
```

### Correction

The original query used fields such as:

```text
Account
Process
CommandLine
```

These were replaced with the appropriate `DeviceNetworkEvents` fields:

```text
InitiatingProcessAccountName
InitiatingProcessFileName
InitiatingProcessCommandLine
```

---

# 4. Suspicious PowerShell + Network

Now combine Day 9 PowerShell hunting with network telemetry.

Interesting indicators include:

```text
DownloadString
DownloadFile
Invoke-WebRequest
IEX
```

### Mission 3

```kql
DeviceNetworkEvents
| where Timestamp > ago(24h)
| where InitiatingProcessFileName =~ "powershell.exe"
| where InitiatingProcessCommandLine has_any (
    "DownloadString",
    "DownloadFile",
    "Invoke-WebRequest",
    "IEX"
)
| project Timestamp,
          DeviceName,
          InitiatingProcessAccountName,
          InitiatingProcessFileName,
          InitiatingProcessCommandLine,
          RemoteIP,
          RemotePort,
          RemoteUrl
```

### Hunting Logic

```text
PowerShell
    ↓
Download Indicator
    ↓
Network Connection
    ↓
Destination
    ↓
Investigation
```

This is much more useful than simply searching for PowerShell.

# 5. Common Network Ports

Ports provide additional context.

| Port | Common Use  |
| ---: | ----------- |
|   80 | HTTP        |
|  443 | HTTPS       |
|   53 | DNS         |
|   22 | SSH         |
| 3389 | RDP         |
|  445 | SMB         |
| 5985 | WinRM HTTP  |
| 5986 | WinRM HTTPS |

> A port by itself does **not** indicate malicious activity. The process, destination, account, and surrounding behavior provide the important context.

# 6. RDP Network Hunting

RDP commonly uses:

```text
RemotePort = 3389
```

### Mission 4

```kql
DeviceNetworkEvents
| where Timestamp > ago(24h)
| where RemotePort == 3389
| project Timestamp,
          DeviceName,
          InitiatingProcessAccountName,
          InitiatingProcessFileName,
          RemoteIP,
          RemotePort
```

This can complement the Day 14 `DeviceLogonEvents` RDP investigation.

```text
Day 14
RemoteInteractive Logon
        ↓

Network connection to port 3389
```

# 7. SMB Hunting

SMB commonly uses:

```text
RemotePort = 445
```

This can be useful when investigating:

* File-share access
* Windows Admin Shares
* Remote administration
* Potential lateral movement

### Mission 5

```kql
DeviceNetworkEvents
| where Timestamp > ago(24h)
| where RemotePort == 445
| project Timestamp,
          DeviceName,
          InitiatingProcessAccountName,
          InitiatingProcessFileName,
          RemoteIP,
          RemotePort
```

### Correction

The original query attempted:

```text
| where Timestamp,
DeviceName,
...
```

Those are fields, not a filter condition.

Use `project` to select them.

---

# 8. Top Network Destinations

### Mission 6

```kql
DeviceNetworkEvents
| where Timestamp > ago(24h)
| summarize Count = count() by RemoteIP
| order by Count desc
```

This identifies the most frequently contacted destination IPs.

### Analyst Warning

A high connection count does **not** automatically make an IP malicious.

It could belong to:

* Microsoft services
* Corporate infrastructure
* CDN providers
* Security products
* Software-update services
* DNS/infrastructure systems

Destination reputation and context are required.

# 🔥 9. Suspicious Process Network Hunter

Combine today's network hunting with previous process-hunting knowledge.

### Hunting Logic

```text

          ↓

          ↓

```

# 🧠 Analyst Challenge

Suppose you discover:

```text
02:15 AM

WINWORD.EXE
      ↓
powershell.exe
      ↓
Invoke-WebRequest
      ↓
10.10.20.55:443
```

From previous days we already have:

```text
Office
 ↓
PowerShell
 ↓
Suspicious Command
```

Day 15 adds:

```text
 ↓
Network Connection
 ↓
Destination
```

### Would I immediately call it malicious?

**No.**

I would investigate:

1. What is `10.10.20.55`?
2. Is it an internal or external destination?
3. Is the destination known?
4. What URL was accessed?
5. What process initiated the connection?
6. What was the complete command line?
7. What file/data was downloaded?
8. What happened immediately after the connection?
9. Did the downloaded file execute?
10. Did the same destination appear on other endpoints?

The combination is **highly valuable as an investigation lead**, but context is required before making a final determination.

## 📚 KQL Concepts Learned

| KQL / Concept                  | Purpose                             |
| ------------------------------ | ----------------------------------- |
| `DeviceNetworkEvents`          | Endpoint network telemetry          |
| `RemoteIP`                     | Destination IP                      |
| `RemotePort`                   | Destination port                    |
| `RemoteUrl`                    | Destination URL                     |
| `InitiatingProcessFileName`    | Process making the connection       |
| `InitiatingProcessCommandLine` | Command responsible for activity    |
| `InitiatingProcessAccountName` | Account associated with the process |
| `has_any()`                    | Search for multiple indicators      |
| `in~`                          | Case-insensitive list matching      |
| `summarize`                    | Aggregate events                    |
| `count()`                      | Count connections                   |
| `project`                      | Select investigation fields         |
| `ago()`                        | Relative time filtering             |

---

## 🎯 Day 15 Key Takeaways

1. Network telemetry connects **process activity to destinations**.
2. `DeviceNetworkEvents` is useful for endpoint network hunting.
3. PowerShell + download behavior + network activity is a valuable investigation lead.
4. Ports such as `3389` and `445` can provide lateral-movement context.
5. A destination IP alone is not enough to classify activity as malicious.
6. Process, account, command line, destination, and timing should be correlated.
7. Network activity can help reconstruct what happened after lateral movement.
